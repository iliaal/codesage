# Entity cards

Use `codesage describe <target> --json` or MCP `describe` with an absolute `project` and a `target`. Targets use the shared resolver: file, symbol, feature, and directory handles, indexed paths, `path:line`, qualified names, bare names, routes, and commands. Directory handles require an indexed descendant under the literal, case-sensitive path; a wrong-case path is a miss. An ambiguous target returns `target.resolved` candidates and no `card`. Choose a candidate's handle and repeat the call.

Each card contains named `sections`. Read `data` for the summary, and call `expand.tool` with `expand.arguments` for its fuller question. Compact detail samples one leading row per list; standard samples five, and full samples up to 100. Counts describe the indexed rows, while `top`, `primary`, and `modules` are samples. Name-based reference counts carry `counts_floor`; dynamic or unresolved calls can be absent, and same-named definitions can share name counts.

Internal imports name indexed definitions or module files. Rust workspace imports also use indexed Cargo feature contexts and package names. External counts cover imports with no indexed destination under those rules. Feature directory entrypoints contribute their indexed subtree to risk rollups. MCP response budgeting can reduce sampled section data; affected sections retain their expansion and report `completeness.kind: "truncated"` with a recovery call.

File sections are `identity`, `symbols`, `dependencies`, `features`, `risk`, `coupling`, `tests`, `boundaries`, and `findings`. Symbol sections are `identity`, `references`, `callees`, `clones`, `features`, `hotness`, and `cycles`. Feature sections are `identity`, `risk`, `tests`, `boundaries`, and `findings`. Directory sections are `module_map`, `fan_in`, `features`, and `risk`. Pass `sections` over MCP or `--sections identity,symbols` on the CLI to request only those facts. An empty list requests no sections; an unknown or inapplicable section fails.

```sh
codesage describe file:crates/graph/src/search.rs --json
codesage describe sym:crates/graph/src/search.rs#search_page --sections identity,references --json
codesage describe dir:crates/graph --detail full --json
```

Compact sections have a 500 ms deadline; risk has 250 ms. Standard doubles those allowances, and full multiplies them by ten, within the enclosing MCP request deadline. A cut section contains `data.unscored`, `completeness.kind: "unscored"`, a reason, and an executable `recover`. Risk reuses current shared ranking assessments when available, retaining their notes and measurement state, and shares graph lookups across scored files. Missing Git history leaves history terms unmeasured; run `codesage git-index` to measure them. Directory and feature risk rollups exclude unmeasured files from max and mean. Warming the ranking does not change those facts or remove the recovery command.

File `lines` and directory line totals count the current regular source files. File `indexed.dirty` compares their bytes with the structural index; symbols and relationships remain indexed facts. Symbol cycle membership describes its file's load-time import component, rather than a function call cycle. Clones use the existing structural MinHash search at Jaccard ≥0.85. The clone search and its expansion seed every fingerprint sharing the resolved bare name, even for a unique symbol handle. `name_union` reports whether any seed is outside the requested occurrence; `target_seeded` reports whether that occurrence supplied a fingerprint. `seed_total` counts distinct fingerprint occurrences, and `seeds` samples their definition handles, file handles, and lines. A missing definition handle leaves the file and line as provenance. The expansion's `target` describes input resolution, rather than seed uniqueness. No signature is fabricated before signature indexing exists.

`findings.open` counts open records in the existing `.codesage/findings/*.json` store. It does not run review or alter finding lifecycle state. A missing store counts zero; an unreadable or malformed store is unscored. The response reports `cost.ms`, `cost.bytes`, and `cost.detail`. Both surfaces open the index read-only, including MCP freshness metadata, and neither loads an embedding model. An older index remains unchanged: missing optional facts are null and named in `identity.unavailable`, affected sections are unscored, and unavailable semantic freshness reads `index.semantic: "unknown"`.
