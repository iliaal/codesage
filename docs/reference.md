# Behavior reference

## Languages

PHP, Python, C, C++, Java, Rust, JavaScript, TypeScript, Go.

C and C++ reference, symbol, and fingerprint extraction skip code inside a literal `#if 0` (and the dead arm of a literal `#if 1`), because a call there exists in no build and would otherwise inflate counts that are published as floors. `#ifdef`, `#ifndef`, and `#if EXPR` stay live in every arm: which of those a build takes is configuration, not dead code. A live arm that holds only part of a statement, such as `else if (...) { ... }` or `catch (...) { ... }` alone inside `#if defined(X)`, can make the parser read the statement as a function definition. C and C++ extraction rejects a function or method named `if`, `else`, `while`, `for`, `switch`, `do`, `return`, `case`, `sizeof`, or `goto`, a definition whose return type is `else`, and, in C++ only, a definition with no return type and no `template` header directly inside a function or lambda body (C keeps GNU nested functions). No symbol or fingerprint row is created, and calls in the arm's body are attributed to the enclosing function. Calls inside the recovered condition itself, such as `foo` in `else if (foo(x))`, are not recovered. `.h` files use C++ when an admitted file with an unambiguous C++ extension sits in the same directory or directly includes the header. Quoted includes try the includer's directory, then the project root; system includes start at the root, and either form can use a unique indexed suffix. Ambiguous suffixes, macro includes, literal dead branches, and transitive includes supply no routing evidence. Without that evidence, a header uses C when the C parse is clean and has no ambiguous macro calls attached to function declarators; a degraded or ambiguous C parse retains the former project dialect (C++ when the admitted project contains an unambiguous C++ file, otherwise C). This fallback preserves recovery of macro-heavy declarations whose C ranges can be incorrect even with fewer errors. `.c` always stays C; CUDA-only files supply no C++ routing evidence. No config knob is required.

Before parsing C++, macro-shaped identifiers ending in `_API`, `_EXPORT`, `_IMPORT`, `_DLLEXPORT`, or `_DEPRECATED` (at least two characters before the suffix, optionally with a parenthesized argument list) are neutralized when they sit in a class head (`class MYLIB_API Widget`) or at the start of a declaration (`MYLIB_API int f();`), so the class, its members, and the function are indexed. A class-head macro becomes spaces; a macro opening a declaration becomes a same-length `[[...]]` attribute, so the definition still starts at the macro for spans, leading-comment rationale, and `edit_check`. Byte offsets, lines, and columns are unchanged. Comments, strings, preprocessor lines, macro-shaped words used as values or as the declared name or type (`class RENDER_API final`, `MY_TYPE_API const x;`), heads that would keep a second type (`void ZEND_FASTCALL f`), and explicit instantiations (`template class FOO_API Foo<int>;`) are left as written; a macro before `friend` becomes spaces. Before parsing C, the same suffixes, `PHPAPI`, and the exact Zend modifiers `ZEND_COLD`, `ZEND_FASTCALL`, and `ZEND_NORETURN` are neutralized only in a function declaration head that retains one type and one declarator name. The opening macro becomes a same-length `extern` specifier, and further macros and arguments become spaces; this retains macro-inclusive spans on otherwise clean declarations without allowing a recovered statement to consume them as attributed bodies. Recorded visibility still comes from the original source, including `static`. Macro-shaped C types and names, unknown second types, comments, strings, and preprocessor lines remain as written.

C/C++ function definitions also recognize a direct macro-wrapped name such as `FNAME(run)(void)` when a preceding top-level definition in the same file proves an exact one-parameter identity macro (`#define FNAME(name) name`). The single bare argument supplies the lexical function name; C++ qualification, original definition ranges, and calls owned by the body are preserved. This does not expand macros. Unknown, conditional, variadic, multi-argument, token-pasting, and other rewriting wrappers are unsupported. Redefinition, `#undef`, includes, and uncertain preprocessor directives invalidate the local proof until a new unconditional identity definition. Prototypes, calls, and function-pointer returns do not become argument-named definitions.

Named C struct, enum, and union definitions require bodies, matching C++ extraction; uses of those types and bodyless forward declarations do not create definition symbols. Named unions use the `Struct` symbol kind, and anonymous unions do not create union symbols.

An import or import-binding directive that loads nothing at module load time is recorded with `lazy: true` (omitted when false): one whose node sits inside a Python `def` or a JavaScript/TypeScript function body that is not invoked where it is written (it loads on use), or a TypeScript type-only directive the compiler erases (`import type`, `export type { .. } from`, `import type X = require(..)`, a clause whose every specifier is `type`, or a binding's own `type` specifier). A clause mixing `type` and value specifiers is load-time. A function invoked in place (`(...)()`, `.call`/`.apply` chains, a `.bind(...)` that is itself called, `new (...)()`) is load-time. C/C++ `#include`, Rust `use`, PHP `use`, Java `import`, and Go `import` are never lazy. Import-cycle detection builds its file graph from directives that name an indexed symbol plus JavaScript/TypeScript relative specifiers and C/C++ quoted includes, each resolved to the first indexed file its resolver would load (TypeScript: `.ts`, `.tsx`, `.d.ts`, then JavaScript; JavaScript: `.js` first; C/C++: the includer's directory, then the project root); a `.d.ts` file is never an endpoint, and `list_dependencies` keeps every candidate. Only emitted JavaScript extensions swap to TypeScript sources (`.js`→`.ts`/`.tsx`/`.d.ts`, `.jsx`→`.tsx`, `.mjs`→`.mts`, `.cjs`→`.cts`). Bare JavaScript specifiers, `<...>` system includes, and includes reachable only through other `-I` paths name no file. A Go `import` or a bare JavaScript/TypeScript import specifier (`'debounce'`) names a package, never a symbol: it forms no cycle edge, no `find_references` `to`, and no `impact_analysis` or reachability dependent. Its bindings (`import debounce from 'debounce'`) and same-named calls are still matched by name. Import-cycle detection (`assess_risk`, `assess_risk_diff`, `review_rehearsal`, `session_start`/`session_end`) drops a file pair whose directives are all lazy; one load-time directive keeps the pair. `list_dependencies`, `impact_analysis`, call resolution, and bundles keep lazy rows. Where the cut applies, `lazy_edges` (present only when nonzero) counts the lazy-only pairs that would close or enlarge a cycle: per file on `assess_risk`, per cycle on `cycles_touching_patch[]` and the rehearsal import-cycle evidence, and on the persisted session snapshot and diff.

C, C++, Rust, PHP, and Java definitions record `visibility` (`public`, `crate`, `module`, `file`, `private`, `protected`; omitted when unknown). A C/C++ `static` function or file-scope `static` object is `file` unless it lives in a header (`h`, `cuh`, `hpp`, `hh`, `hxx`, `h++`, `tpp`, `ipp`). A non-static C function definition outside another function and outside a header is `public`. PHP functions are `public`; methods use their explicit access modifier or PHP's implicit `public`, including static methods. Java methods and constructors use explicit public/private/protected modifiers; package access remains unknown. A Rust item is `public` / `crate` / `module` from its `pub` modifier: `pub(crate)`, `pub(super)`, and `pub(in path)` are `crate`, `pub(self)` and no modifier are `module`, and `impl Trait for Type` methods are always `public`. Callee resolution (`impact_analysis`, `trace_call_path`, `export_context`, the `to` handle on `find_references` rows, and the `reachable` walk behind `recommend_tests` / `review_rehearsal`) filters candidates by recorded visibility: `file` requires the same file; Rust `module` and `crate` use indexed module descendants and shared targets when known, falling back to path approximations when unresolved. An undecidable crate boundary admits. PHP/Java class access is recorded for display but does not add access-control filtering to call resolution. A gate survivor of a same-named set still needs same-file or import evidence. `find_references` rows stay name-based (a C `static` called from another file is still listed), but such a row carries no `to`.

Callable symbols carry `signature` with the source `declaration` before the body, structured `parameters` (`declaration`, nullable `name`, `type_name`, and `default_value`, plus `optional` and `variadic`), nullable `returns`, and nullable `arity` (`minimum`, nullable `maximum`). These are syntax declarations, without inferred runtime types. `optional` records declared optional/default syntax; it does not establish that a caller may omit the argument (PHP can require a defaulted parameter before a required one). Arity is a separate bound. Defaults retain literal whitespace; Go grouped names become separate parameters. All nine languages support ordinary callable declarations, including overloads as separate symbol rows. C/C++ pointer and reference declarators retain their syntax, including source calling-convention annotations in return declarations; declarations containing multiple declarators and unexpressible return forms remain unknown. Constructors and JavaScript functions have no declared return type. Arity describes accepted positional argument counts where syntax establishes them: an absent maximum is unbounded; an absent arity is unknown. JavaScript, C empty parameter lists, Rust receivers, Python class-owned methods, Python positional/keyword separators and splats, and TypeScript `this` parameters or typed rests other than direct arrays have unknown arity (tuple and alias expansion is not modelled). PHP's accepted extra positional arguments leave its maximum unbounded. Missing signatures, names, or return declarations do not imply an empty parameter list or a void return.

Migration `0027_symbol_signatures` adds nullable `symbols.signature`, `arity`, `parameters`, and `return_type` columns without rewriting existing rows. Existing symbols retain unknown signatures until the next `codesage index`; the structural extraction interpretation bump reparses unchanged files.

`is_test` is stored on files and symbols and emitted on symbol and reference rows (omitted when false). `files.is_test` is the discovery path heuristic (`TEST_LIKE_EXCLUDE_PATTERNS`: `tests/` / `test/` / `__tests__/` directories, `*_test.go`, `*Test.php`, `*.test.ts`, `*.spec.js`, `test_*.py`, `*_test.rs`, `*.phpt`, `benches/`, ...) or the parser's file-level verdict: a JavaScript/TypeScript program whose top level calls `describe` / `it` / `test`, or a Rust file headed by `#![cfg(test)]`. Every symbol in a test file inherits the flag, and the watcher applies the same rule. The parser adds symbol-level marks, ancestors included: Rust items inside a module gated by `#[cfg(test)]` or by a `cfg(all(...))` naming `test` anywhere in its list, at any depth, and functions carrying `#[test]`, `#[tokio::test]`, `#[rstest]`, `#[sqlx::test]`, `#[async_std::test]`, or `#[test_case]` (`#[cfg(feature = ...)]`, `#[cfg(not(test))]`, `#[cfg(any(test, ...))]`, and `#[cfg_attr(test, ...)]` do not count; `#[cfg(test)] mod helpers;` marks the declaration and not the `helpers.rs` it names, which falls back to the path heuristic); Python `test_*` functions, `Test*` classes (uppercase or digit after `Test`, so `Testament` is not one) and their methods, and definitions decorated `@pytest.mark.*` or `@pytest.fixture`; JavaScript/TypeScript definitions nested in a `describe` / `it` / `test` call (member forms such as `describe.skip` and `test.each(...)(...)` count) and every definition in a file whose top level makes such a call; Java methods annotated `@Test` or `@ParameterizedTest`, simple or qualified. Go, PHP, C, and C++ rely on the file heuristic only. A reference is test code when its file is, or when the narrowest definition whose line range contains the reference is; `refs` stores no flag, the value is derived at read time. Consumers: `assess_risk` `top_symbols` skips test symbols; `project_overview.top_risk_files` skips test files unless called with `include_tests: true`, which computes a fresh ranking outside the shared cache, while the `session_start` / `session_end` top-50 baseline always skips them; `list_dependencies` moves an import target named only from test code into `test_imports` (a target also named from product code stays in `imports`; in a test file everything is a test import); `search` demotes test chunks from `files.is_test`. A row indexed before `0024_is_test` reads `is_test` 0, so ranking and search fall back to the path heuristic for files whose stored interpretation is older than `STRUCTURAL_INTERPRETATION`, and parser-level symbol marks appear only after the next `codesage index`.

Rust external `mod` declarations establish file dependencies and module context within conventional Cargo targets: `src/lib.rs`, `src/main.rs`, and flat or directory targets under `src/bin/`, `tests/`, `benches/`, and `examples/`. A module declaration does not import its functions into the caller's scope. Included files that could also be standalone targets receive a dependency note. Custom Cargo manifest paths, `#[path]`, `include!`, and inline caller-module scope are not modelled. Context construction stops after 16,384 module contexts; dependency notes, reference `to_resolution.capped`, trace/bundle/impact `bounded`, and test-reachability flags disclose affected incomplete results.

Rust 2018/2021/2024 external-crate calls also resolve through normal, non-optional Cargo path dependencies inside the indexed project. Resolution follows workspace-inherited dependencies and editions, package aliases, explicit library names, top-level named imports, and public named re-export chains within each dependency's conventional `src/lib.rs` library and file modules. Only recognized conventional Cargo target contexts participate; configured build-script paths are excluded. Conventional binary and integration-test targets can name their package's library. The resolver reads manifests without executing Cargo and verifies source hashes against the index before using imports or exports. It refuses source-declared private, ambiguous, stale-source, or shadowed matches. Explicit macro invocations and custom rewriting attributes can leave affected spellings unresolved; procedural expansion and generated sibling bindings remain unmodeled. Custom library paths, dev/build/target-specific dependencies, globs, inline modules, and attributed exports other than `#[doc]` remain unsupported. Callers and dependency libraries must use one of those editions. External resolution shares a 2 s budget, 64 reads, and 8 MiB per resolver; each export walk allows 32 states. Existing `bounded` and `capped` disclosures cover exhausted limits.

Incremental structural indexing compares detected language, raw content hashes, and each file's structural interpretation identity. Header routing is shared by discovery, incremental indexing, the watcher, semantic coverage, and overlays. Changes to admitted headers or C++ evidence invalidate affected cached decisions; unchanged content and routing context reuse prior decisions. Removing C++ sources retains current header rows when every surviving C++ source and every admitted header keep their paths, raw hashes, and selected languages. C++ additions or edits, failed context reads, and previously stale rows still require revalidation. Adding or removing sources is compared against fresh discovery. Overlays disclose stale data when new or newly excluded routing candidates require persistent indexing, rather than inferring membership from the old index. When project configuration cannot be read, overlays requiring header routing retain indexed facts and disclose that working-tree edits were not checked; other structural overlays remain available. Parser, extraction, and trust-boundary rule changes must bump the relevant component of `STRUCTURAL_INTERPRETATION` in `crates/graph/src/index.rs`; the next `codesage index` reparses unchanged files carrying an older or missing identity. Each successful per-file transaction records its identity, so failed or untouched files remain stale. Structural rewrites invalidate semantic reuse for that file across models so the next semantic pass refreshes symbol-derived headers. Content hashes remain raw file hashes for watcher, staleness, and feature-map consumers. `codesage status --json` reports `interpretation.current`, stored-version file counts, `unrecorded_files`, and `stale_files`.

Schema migrations `0022_refs_lazy` (`refs.lazy`), `0023_symbols_visibility` (`symbols.visibility`), and `0024_is_test` (`files.is_test`, `symbols.is_test`) are additive; existing rows read as not-lazy, unknown visibility, and not-test until the next `codesage index` reparses them. Schema migration `0019_file_hash_cache` stores verified content hashes with size, nanosecond modification/change times, and observation time. Incremental discovery reuses a hash only when the stat triple matches and both timestamps precede the observation's whole second; full indexing bypasses reuse. Files still undergo access checks. Platforms without the required timestamps hash normally. This cache does not attest structural parsing or semantic fingerprint freshness.

Search applies a separate ranking penalty to paths under `bench/` or `scripts/`: a 0.15 score multiplier unless the query matches the path or platform-intent heuristic. Exemptions include recognized source paths, directory/glob forms, and supported platform or portability keywords. A result already receiving the ordinary non-test-query test penalty does not receive that auxiliary penalty again. This ranking change is independent of the MCP search payload projection; projection itself preserves the ranked results.

## MCP tools

`find_symbol` rows and `describe` symbol identity sections retain `signature` at every detail level, including default and compact responses. CLI `codesage find-symbol <NAME> --json` exposes the same persisted fields. File cards include `public_api`: public symbol handles, kinds, and signatures, capped at 1/5/100 rows for compact/standard/full detail. `total` and `truncated` disclose omitted rows; `unknown_visibility` counts symbols without visibility evidence, and `missing_signatures` counts public symbols without a callable signature, including non-callables. `counts_floor` marks this as the recorded public surface, not a complete export or ABI inventory. C file-local static functions and PHP/Java private or protected methods are excluded; public static PHP/Java methods remain included.

`edit_check` may reuse persisted declarations and arity only when one read snapshot proves the indexed language, structural interpretation, and exact SHA256 content hash match the pinned HEAD blob. Missing, old, malformed, or stale cache data falls back to source extraction. HEAD is still parsed to locate declarations, establish scopes and overloads, and inspect callers; reuse removes duplicate signature extraction, not the analysis parse. Working-tree edits and stale index contents cannot replace the pinned source.

One target grammar (`crates/graph/src/resolver.rs`) covers the tools that name an entity: a handle (`sym:<path>#<qualified>[@<line>]`, `file:`, `dir:`, `chunk:`, `feat_`), an indexed path (a leading `./` is ignored), `path:line`, a qualified name, a bare name, `route:METHOD path`, or `cmd:name`; anything else is text a semantic search may take. Every tool that names an entity spells it `target`, or `targets` on the file-set tools; the legacy argument (`name`, `symbol_name`, `file_path`, `file_paths`, `feature_id`), deprecated since 0.35.0, is still accepted, and the two naming different things is `E_PARAM` quoting both. `find_symbol`, `find_references` (`name` stays its primary spelling; rows are keyed by the bare names of the definitions the input resolves to, so a `sym:` handle returns the union those names already are and the envelope discloses every definition sharing them), `find_similar`, `impact_analysis` (`dir:`, `chunk:`, and `feat_` are `E_PARAM` there), `export_context`, and `feature_bundle` take the whole grammar; `trace_call_path` has no single target and takes it on `from` and `to` instead; `edit_check` takes a `sym:` handle naming its own `file_path`. The file-grained tools (`list_dependencies`, `find_feature`, `find_coupling`, `assess_risk` / `assess_risk_batch` / `assess_risk_diff`, `recommend_tests`, `review_rehearsal`) take the arms that carry a file (`file:`, `sym:`, `chunk:`, an indexed path, `path:line`) and answer for the file the target lives in; a `dir:`, `feat_`, `route:`, or `cmd:` target is `E_PARAM` naming what they take. What a miss costs there depends on the grain: a one-target tool asks the resolver for nearest candidates and refuses with `E_NOT_FOUND` and their handles, so a bare basename or a path spelled from a subdirectory says where the file is (a path the working tree holds as a file is taken as written instead, so a file the caller just wrote reads as unindexed rather than as a miss), while a file-set tool passes an unmatched path through to its own per-input disclosure (`unscored_files`, `unindexed_files`) rather than costing every other input its answer. One ambiguity policy follows from the grammar: tools whose answer is a union of per-definition answers (`find_symbol`, `find_references`, `find_similar`) return the union and disclose it in `target`; tools whose answer would be wrong as a union (`impact_analysis`, `trace_call_path`, `export_context` on a symbol, `feature_bundle`) return `E_AMBIGUOUS` with `candidates` and a remedy that replaces the input with the first candidate's handle, and `edit_check` returns `E_AMBIGUOUS` with a remedy carrying the first matching `line`.
- `help`: tool, field, error, recovery, and task-recipe reference. Requires an absolute existing `project` directory; no index, Git repository, watcher, or model inference is required. Select `tool`, `tool` plus `field`, an envelope `field`, `code`, or `intent`; other selector combinations are `E_PARAM`. Field paths accept `input.<field>`, `output.<field>`, and nested arrays such as `output.results[].score`. Intents are `review`, `fix_bug`, `rename`, `add_feature`, `before_commit`, and `debug_failure`; recipes include ordered call templates, argument bindings, rationale, and stopping conditions. Tool schemas come from the live router; prose comes from `plugins/codesage-tools/skills/codesage-retrieval/references/help.json`, also used by the retrieval skill. `tool: "daemon"` lists operator controls; `tool: "daemon_stats"` documents the unadvertised diagnostics tool. `price_list` reports measured daemon-lifetime latency histograms across all projects and outcomes, with sample counts; disabled diagnostics or no completed requests reads `unknown`, never an estimated latency.
- `describe`: one card for a file, symbol, feature, or directory, with per-section evidence and expansion calls. Its `findings` section reads plugin-persisted `.codesage/findings/*.json` and contains `{open, ids[], top[]}`; each top row is `{id, severity, title, line}`. Rows rank by severity (`high`, `medium`, `low`), file, line, and ID; duplicate IDs count once. Compact, standard, and full return at most 1, 5, and 100 findings, respectively, while `open` keeps the total and `truncated` discloses omitted rows. Missing storage omits the section; a valid empty store returns zero; malformed, unreadable, or symlinked storage makes the section unscored. Genuine transfer records do not count as open findings; malformed transfer metadata is unscored. Reads stop at 512 directory entries, 1 MiB per ledger, 10 MiB in total, or 4,096 records.
- `edit_check`: compare a complete proposed replacement declaration against a symbol in pinned Git HEAD, without writing source, requiring an index, or starting a watcher. Requires absolute `project`, repository-relative `file_path`, the declaration as `target` (legacy spelling `symbol_name`), and `replacement`; optional one-based `line` disambiguates declarations. Reports arity, visibility, and same-scope overload snapshots plus working-file divergence. Provably incompatible caller checks cover same-file Rust free functions reached through explicit `self::` / `super::` paths, without imports, macros, or attributes. Other languages receive syntax-level declaration diffs; methods, indirect/external callers, and unsupported parameter semantics remain unknown. `target` also accepts a `sym:` handle naming the same `file_path` (its `@<line>` supplies `line`); a handle for another file is `E_PARAM`. Ambiguous `.h` dialects are refused (`E_PARAM`, like a malformed `replacement`); no matching declaration is `E_NOT_FOUND`, several are `E_AMBIGUOUS` carrying `candidates` (`sym:<file>#<name>@<line>`) and a retry with the first matching `line`. This is not a compilation or safety verdict; source and proposed file are capped at 1 MiB, caller output at 100. The response envelope opens an existing index read-only for its `index` block and stale-path annotation; a project without one still answers.
- `project_overview`: first-call orientation with languages, structural + semantic freshness, feature summary by kind, a module map, product-first entrypoints, hot symbols, separate product and test risk, trust-boundary clusters, and test conventions. `module_map` groups indexed files by their nearest non-root package manifest, falling back to the top-level directory or `.` for root files. Rows report files, measured lines, symbols, product symbols, languages, and the fraction of files marked as tests. Line counts read current regular files on every call, up to 10 MiB per file and 32 MiB per project; `unmeasured_files` discloses unreadable or unmeasured files. Other counts describe indexed or overlaid facts. Entrypoints rank product paths before bench/scripts/examples and tests, then by kind, entry-file fan-in, and churn; the 15-row cap first includes a representative of each available kind in a path class. `hot_symbols` contains ten product symbol handles ranked by name-based reference sites; `fan_in` can conflate same-named definitions and omit dynamic uses. No model inference runs. The daemon shares a generation-validated top-50 product ranking with `session_start` and caches a separate test ranking; overview shows ten rows from each as `top_risk_files` and `top_risk_tests`. Freshness remains per request. `include_tests: true` computes an uncached merged `top_risk_files` ranking while retaining the separate `top_risk_tests`. The static `suggested_next_calls` field is removed; evidence-derived MCP `next[]` remains, and `recovery[]` carries CLI commands for stale structural data, unavailable semantic coverage, or missing Git history. Call once at session start. `freshness` pairs `commits_behind` with `indexed_files_behind`: the indexed files whose HEAD content differs from the index, so a five-commit range that touched only unindexed paths reads `0` and suggests no reindex (absent when the comparison could not run, `indexed_files_behind_bounded` when it stopped at its 2,000-path cap or 500 ms budget; a bounded `0` is unmeasured, not fresh, and still nudges a reindex). A supported source file committed since indexing counts as behind; a path discovery would skip (no parser, hidden, matched by the default or `[index] exclude_patterns`, `.gitignore`d but force-added, or a symlink) does not. The `git diff`, the `.gitignore` and symlink lookups, and the blob comparison share that 500 ms budget, and a `git` child still running when it expires is killed. The HEAD and ancestry lookups before it run under 2 s deadlines, so one check takes at most about 4.5 s unless the kernel cannot interrupt the stalled child; a timed-out lookup reads `unknown` and logs a warning. `hook_health` (`installed_hooks`, `last_run`, `last_exit`, `lock {state, reaped}` plus `pid`, `since_unix`, `since`, and `age_secs` only when the lock is held) reports the indexing-hook lock state; absent when the project is not a Git repository; the overview never reaps, `codesage doctor` does. When the `semantic_files` table cannot be read (missing or malformed), `freshness.semantic_unavailable` names the reason, `semantic_indexed_files` is not a measurement, and `recovery[]` includes `codesage index --full` (after the stale-index nudge when one applies); the structural half of the overview is still returned. Every writable open recreates a malformed `semantic_files` table empty (forcing a re-embed), so this state is mostly seen through read-only handles.
- `search`: semantic search with embedding + reranking; each page carries `confidence` / `margin_pct` / `cliff_at` (relevance-cliff disclosure). At the default MCP `standard` detail, a high-confidence cliff removes only `content` from rows below the cliff; all rows retain their identities, order, scores, paths, ranges, and annotations. Flat pages retain source everywhere. `detail: full` restores all source content, while `compact` keeps its existing source-free projection. Opt-in `adaptive_limit` still cuts rows at the cliff. Projection does not change ranking, CLI search output, or the graph search result; explicit response budgets can still truncate the projected payload. Optional `explain: true` (CLI `--explain`) adds a per-row `trace` of score transitions and retrieval/reranker signals; it leaves ranking unchanged and is omitted by default. Each surviving trace is complete and ends at the row's score. MCP budgeting can shorten content or annotations, or drop whole rows, disclosed as `completeness.kind: truncated`. An attempted BM25 lookup failure keeps available dense results and adds `lexical_fallback_reason`, even without `explain` or on an empty page; a successful lookup with no lexical matches adds nothing. MCP reports `partial` with `recover: {reason: "lexical_lookup_failed", command: "codesage index --full"}`; truncation preserves the reason and both completeness kinds. Human CLI output warns on stderr; JSON carries the same reason. See `bench/search-explain.md` for diagnosis and comparison limits.
- `find_symbol`: symbol definitions by name, handle, or `path:line`. Rows carry `handle` (`sym:<path>#<qualified_name>`, line-independent; `@<line_start>` is appended only when several definitions in that file share the qualified name), `visibility` when known, and `is_test: true` for test code (see Languages; omitted when false). The envelope is `{results, target}`: `target` carries one candidate handle per definition, `ambiguous`, `candidates_total`, and `overloads` (definitions sharing one file and qualified name, omitted when zero). Module declarations (`mod x;`, a module or namespace symbol with no body on its line) are excluded from both unless `kind` is `module` or `namespace` (CLI: `--include-modules`); a `kind` filter narrows both too, so `target.ambiguous` counts only definitions of that kind. A name that matches nothing as written returns no rows and case- or suffix-matched leads in `target.resolved`, each below the `0.8` confidence a caller may act on.
- `find_references`: references to a symbol; `name` (or `target`) takes the target grammar, and since rows are keyed by the bare names of the definitions it resolves to, a `sym:` handle returns the rows that definition's bare name does, with `definition_count`, `ambiguous`, and `note` covering every definition sharing that bare name while `target` stays the input's own resolution (split the union by `to` or `from_file`). An exact qualified spelling keeps its own narrower rows and definition set. Each row's `from_symbol` names the enclosing caller (null at file scope). Rows carry `from` (`sym:` handle of the enclosing symbol, omitted at file scope) and `to` (`sym:` handle of the definition the reference resolves to when the spelling is qualified, the definition is in the same file, or the caller file imports the definition or references its owning type; omitted otherwise). `to` resolution is bounded (256 distinct caller/name pairs, 750 ms); a page that hit the bound carries `to_resolution {resolved_pairs, capped: true}` and rows after the stop have no `to`. `lazy: true` marks a function-body or TypeScript type-only import; `is_test: true` marks a reference made from a test symbol or test file, so rows without it are product callers. The envelope carries `counts_floor: true` (name-based edges; an empty result means none found, not none exist), `definition_count`, `ambiguous` with a `note` when several same-named definitions make the rows a union, and one handle per definition so the union can be split: in `target` when the input was the bare name, in `note` otherwise. `definition_count` and `target` exclude module declarations; the rows are unfiltered, so a `mod render;` line is itself listed as a reference to `render`
- Handles: symbol rows (`find_symbol`, `export_context` / `feature_bundle` `symbol_definitions`, `trace_call_path` steps, `impact_analysis` `sibling_symbols`) carry `sym:` handles; file-shaped rows (`impact_analysis` results, `list_dependencies`, `find_coupling`, `assess_risk*` entries and `top_coupled`, `recommend_tests` coupled/reachable, resolved `from_trace` frames) carry `file:<path>`; `assess_risk_diff` clustered directories carry `dir:<path>`; search and bundle chunks carry `chunk:<path>:<start>-<end>`; features keep `feat_`. Inside a handle's path or name, `%`, `#`, and `@` are written `%25`, `%23`, `%40`; `Handle::parse` in `crates/protocol/src/handle.rs` rejects absolute paths and `..` segments, and no handle is emitted for a path it would reject. Handles are also input: every tool listed at the top of this section takes one as `target` (or as an entry of `targets`), and a `next` follow-up names its subject with the row's own handle whenever the row carries one of the grain the follow-up needs.
- `find_similar`: near-clone detection: functions/methods structurally similar to a named one (MinHash over AST shape, identifiers/literals ignored), ranked by Jaccard. `name` takes the target grammar; fingerprints are keyed by bare name, so a `sym:` handle or `Foo::run` returns the rows `run` does. Rows are the union across every definition sharing that name, with `target` disclosing them. Test files excluded. Needs fingerprints from a reindex.
- `list_dependencies`: immediate file dependencies. `imports` and `test_imports` contain deduplicated internal `file:` handles; destinations use each import site's test flag, product handles take precedence over duplicate test handles, and empty `test_imports` is omitted. Only imports proven to target the same file are suppressed, counted by `intra_file_imports`; genuine cross-file Rust `self::` and `super::` imports remain. `externals` counts distinct product/test import spellings from proven Rust standard-library or manifest-declared registry/Git packages, with `packages_total` and at most five `top_packages`, ranked by total import count and then package name. Path dependencies resolve internally when proven. Unknown imports, unsupported package resolution in other languages, and ambiguous internal matches remain in `unresolved_imports` with their target, test flag, reason, and candidate handles. A spelling with both proven and uncertain import sites retains the established dependency and its unresolved evidence. Missing files or matching bare symbol names alone do not prove a dependency or external package. `detail: full` restores the original product/test spellings in `raw_imports`, retaining the historical spelling partition even when identical spellings resolve differently at separate sites; CLI `codesage dependencies <FILE> --detail full` does the same; the CLI accepts `compact`, `standard`, and `full`, defaulting to `compact`. `imported_by` retains its existing indexed reverse-dependency semantics. `note` discloses module-context limits or ambiguous roles.
- `trace_call_path`: shortest call chain from one symbol to another, breadth-first over resolved callee edges. Each step names the symbol, its file:line, and `call_line` (the line in the previous step's body where it is invoked). `from` and `to` each name one definition: several is `E_AMBIGUOUS` with their handles, and a name that matches nothing returns `found: false` with the nearest candidates in `note`. `bounded: true` means the search stopped at a limit, so an empty answer is not proof no path exists.
- `from_trace`: map a pasted stack trace or sanitizer report (Python, PHP incl. Xdebug, Rust, Java, Go, Node/JS, gdb/ASan/UBSan; Kotlin frames parse with the Java syntax, but a Kotlin frame that names a `.kt` file is always `unresolved` since Kotlin sources are not indexed) onto indexed symbols and `file:line`, innermost-first; `frames[0]` is the innermost frame of stack 0 (Java's deepest `Caused by`, with `Suppressed` blocks last; Python's first traceback; ASan's access stack; Go's `[running]` goroutine; one Rust stack per panicking thread), with `stack` per frame and `stacks` + `root_cause_first` on the report. Each frame is `resolved` (`symbol` may be null between definitions; `with_symbol` counts), `ambiguous` (path suffix or qualified name matched several entries, or only a bare name matched, which is a lead; `candidates` holds at most 10 (5 when the frame names no file), `candidates_total` the count), or `unresolved` (vendor/stdlib/runtime file outside the index); nothing is guessed, and bare names never cross languages. PHP `#N file(line): func()` frames resolve `func`'s definition by qualified name (`Ns\Class\method` as the index stores it), since that `file:line` is the call site. CLI: `codesage from-trace [FILE|-]`.
- `impact_analysis`: files affected by changing a symbol or file, with distance and reasons. A target naming several definitions is `E_AMBIGUOUS` with a handle per definition and a retry remedy (including definitions that share a qualified name, which earlier releases answered for jointly); one naming nothing is `E_NOT_FOUND` with the nearest candidates, not an empty result; a `dir:`, `chunk:`, or `feat_` handle is `E_PARAM` naming the accepted kinds (`sym:` / `file:` handle, indexed path, qualified or bare name). `is_file` is deprecated: a handle names its own kind and outranks it. Opt-in `include_forward` (forward deps), `include_siblings` (same-file symbols), `limit`, and `summary_only` controls; result is an object with `results` plus the requested extras. Optional `bounded: true` discloses incomplete Rust module resolution.
- `export_context`: curated code bundle for the shared target grammar or free text, optionally with callers/callees. Entities resolve before model loading: ambiguous targets return `E_AMBIGUOUS` with their handles, and missing explicit entities or nearest-candidate guesses return `E_NOT_FOUND`. Only a resolver `Text` result uses semantic search. File and directory targets read stored chunks in path/line order; chunk targets read stored chunks overlapping their range and restrict definitions to that range. Feature, route, and command targets use `feature_bundle`'s curated file selection; when entry-symbol and stored-chunk lookup yield no definitions, exports collect available Entry/Owned definitions up to `limit`. Standalone `feature_bundle` retains its entry-symbol/chunk definition selection. `limit` caps primary chunks, definitions, and related chunks on file/directory/chunk targets; zero uses the structural default of 5. Entities without stored chunks keep `found: true` and available structural definitions. Deprecated `is_symbol` forces symbol lookup only for unresolved text; that legacy miss keeps `found: false`. Optional `bounded: true` discloses incomplete Rust module resolution in related context.
- `find_coupling`: files that historically change with a given file (V2b). Each row carries `recurrence` (distinct 90-day calendar windows the pair co-changed in), `span_days` (oldest to newest shared commit), `span_known` (false for rows indexed before recurrence tracking), `recurring` (`span_days >= 30`; `recurrence` alone is informational since a boundary straddle can read 2), `p_cochange` = P(row file changes | this file changes), and `p_reverse` (deprecated spellings `confidence` / `reverse_confidence` since 0.35.0, still emitted); both are lower bounds (commits touching >30 files add no pair evidence but count in the denominator). Non-recurring pairs rank at half weight (`CODESAGE_COUPLING_RECURRENCE=0` or `false` disables). A page with no recurring pair carries a `note` that says whether the indexed co-change evidence is too short (<30 days), the index needs `git-index --full`, or the coupling is short-burst evidence. Any returned unknown-span row adds a `span unknown` note with the `git-index --full` remedy, including on mixed pages with recurring rows.
- `assess_risk`: risk score for a single file (V2b slice 1; now blends import-cycle membership alongside churn / fix / blast / coupling / test-gap). A file with no `git_files` row reports `unscored: true` and a note: churn, fix ratio and coupling pressure were not measured rather than measured as zero, so the score covers structural signals only and must not be read as low risk. `top_coupled` is recurrence-ranked like `find_coupling` (rows carry `span_days` / `span_known` / `recurring`); coupling pressure reads the raw top ten, the coupled-test check reads the raw and ranked pages, and a note names coupled tests that fall below the ranked list. Notes distinguish known one-offs from unknown spans and give the `git-index --full` remedy for unknown spans, including hidden coupled tests and mixed pages. `top_symbols` ranks product symbols only; `is_test` symbols (a `#[cfg(test)]` module and its helpers) are skipped. Its ref counts are resolved product callers, not name matches: a callsite counts only when it resolves to that definition under the rules in Languages and is not itself test code, so a same-named definition elsewhere lends nothing. Resolved counts are lower bounds: a spelling the resolver cannot tie to the definition is dropped. Rust workspace calls resolve within the manifest, import, and public-export limits in Languages; unsupported cross-crate calls still contribute nothing. `shared: true` marks a count several same-named definitions in the same file still answer, and `bounded: true` a row left on its name count because a per-file resolution limit (40 symbols, 20,000 rows, 750 ms) or the 3 s budget one `assess_risk_diff` / `assess_risk_batch` request shares had run out when its same-named group came up, or because the name's own row count exceeded what was left of the row budget (that name is skipped, not hydrated, and the next name still resolves). The limits are checked before each group is hydrated, not enforced mid-group: the group that finds them satisfied is resolved whole, so a pass can overshoot the symbol and time limits by one group.
- `assess_risk_batch`: per-file risk for N files in one call, no aggregation. Use when you have a list of files and want each one's score; saves the per-file MCP round-trip overhead vs N `assess_risk` calls. For patch-level aggregation use `assess_risk_diff` instead.
- `assess_risk_diff`: aggregate risk for a patch / set of files (V2b slice 2). `max_score` / `mean_score` / `max_risk_file` cover scored files only: unscored files are excluded from the aggregates and named in `unscored_files`, while still appearing in `files` and the structural rollups; `scored_file_count` reports how many files were scored, which is the mean's denominator. `max_risk_file` is omitted when nothing was scored. For indexer-written data the exclusion cannot hide a threshold crossing: the terms reachable without a `git_files` row sum to 0.41, under the 0.50 max-score gate, and `review_rehearsal` reads per-file rows rather than the aggregates. The margin is zero: adding coupling pressure reaches exactly 0.50, which the `>=` gate would fire on. The schema does not itself forbid a visible co-change pair without a `git_files` row, so treat the bound as a property of what the indexer produces, not of the types. Per-file `notes[]` may contain short codes (`"T"`, `"NG"`, `"US"`, `"UI"`); resolve via the top-level `_legend` map.
- `recommend_tests`: tests an agent should run after editing a set of files (V2b slice 2). Three buckets: `primary` (sibling conventions plus any changed file that is itself a test), `coupled` (co-change history; entries carry `span_days` / `recurring` and follow the `find_coupling` ranking, one-offs at half weight; only the top 20 co-change partners per changed file are consulted and a note names inputs where more existed), and `reachable` (test files with a resolved call/import path into the changed set within two hops, ranked by distance then `edge_count`, capped at 50 with `reachable_total` carrying the full count). Changed tests are walked too, so a base test class lists the tests that extend it. Read `reach_walk_capped` before trusting an empty or short list: when it is `true`, `reachable` is a lower bound and `unmodelled` means nothing; `unwalked_files`, `partial_files`, `unindexed_files` (a supported-language path the index does not hold: new file, non-repo-relative path, or excluded by `[index] exclude_patterns`), and `no_symbol_files` say why. `unsupported_files` (no parser: CHANGELOG.md, lockfiles) are skipped and never cap the answer. The walk spends one pool of resolution steps in request order with a floor reserved for each queued input, so put the files you care about first. Fixture directories (`fixtures/`, `stubs/`, `testdata/`, `__snapshots__/`) never appear in any bucket. `CODESAGE_REACH_BUDGET` (default 1,500,000 steps, one pool per request) and `CODESAGE_REACH_DEADLINE_MS` (default 5000; `review_rehearsal` uses 1500 regardless) bound the walk. `commands[]` turns the buckets into runnable shell commands (`command`, `covers`, `framework`, `source` = `inline` | `feature_test_command` | `convention`, in that order): `cargo test -p <crate> <module>::` per inline test module and `cargo test -p <crate> --test <name>` per Rust integration test (more than three targets in one crate collapse to `cargo test -p <crate>`), `pytest <paths>`, `php artisan test` / `vendor/bin/phpunit <paths>`, `php run-tests.php <dir>` per `.phpt` directory, `go test <dirs>`, `npx vitest run` / `npx jest` / `npx mocha` / `node --test` / `bun test` / `npx playwright test` `<paths>`, chosen from the test file's runner import, then the nearest `package.json` (`scripts.test`, a single declared runner dependency, a `jest` key) or a vitest config beside it, walking up to enclosing packages (a nested package's command is `(cd -- ./<dir> && …)`; a path no evidence names a runner for gets a note and no command), `mvn -Dtest=... test` / `gradle test --tests ...`, plus a mapped feature's own `test_command`. Paths are single-quoted when they contain shell-significant bytes and prefixed `./` when they start with `-`. A path holding a regex metacharacter (`[`, `(`, `{`, `*`, `+`, `?`, `^`, `$`, `|`, `\`, or a `.` in a directory component, such as `app/v1.2/`), such as a Next.js `[slug]` or `(group)` segment, switches its jest command to `npx jest --runTestsByPath` and is regex-escaped for `npx playwright test`; a `.` only in the file name keeps the plain spelling. vitest (substring filter) and mocha (an existing file is taken literally) keep metacharacter paths as is, except that vitest cannot load a path containing `?` or `\` (Vite reads them as a query and a separator), so such a path gets a note and no command. `npx` passes its arguments to `sh -c` and quotes one only when it holds a byte from npm's own list (whitespace, `"`, `#`, `$`, `&`, `'`, `(`, `)`, `*`, `;`, `<`, `>`, `?`, `\`, a backtick, `|`, `~`); an argument with `[`, `]`, `{`, or `}` and none of those would be globbed again, so only then is the command written `npx -c '<runner> <args>'`. `node --test` globs every argument and reads a leading `-` as an option even after `./`, so a path starting with `-` or holding `*`, `?`, `[`, `]`, `{`, `}`, `\`, or an `!(` / `@(` / `+(` extglob gets a note and no command, as does a `bun test` path containing `?` or `\`; a feature command containing a newline is dropped with a note. `inline_test_modules[]` names Rust `#[cfg(test)]` modules and Python `test_*` functions inside the changed files (`file`, `module`, `test_count`; the Rust count reads `#[test]`, `#[tokio::test`, `#[rstest`, `#[sqlx::test`, `#[async_std::test`, `#[test_case` from source up to 1 MiB, else indexed `test*` function names). Both derive from `primary` + `reachable`, never `coupled`; nothing is executed; omitted when empty. `review_rehearsal` quotes up to five commands in `summary_notes`.
- `review_rehearsal`: predict severity-ranked review objections for a patch (missing tests, unscored risk, high-risk / blast-radius / fix-prone / hotspot files, import cycles, trust-boundary expansion, feature-test gaps, and `scope-spread` when a patch touches ≥4 unrelated feature areas) with hot-symbol evidence. `unscored-risk` is Low for a mixed patch and Medium when every file lacks indexed git history; run `codesage git-index` and repeat the rehearsal. Structural warnings remain available, with unscored risk bands qualified as structural-only. Composes `assess_risk_diff` + `recommend_tests` + drift + feature mapping; read-only, no AI prose. Use as the last step before a commit.
- `session_start` / `session_end`: snapshot structural state at the start of an editing session, diff at the end. Returns `pass: bool` plus new/resolved cycles, per-file risk regressions on the top-50 baseline, and added/removed files. Note the shape divergence: MCP `session_start` returns the compact `SessionStartReport` (`snapshot_path` + counts), while CLI `codesage session-start --json` prints the full `SessionSnapshot` (file list, cycles, top-risk files). In a Git repository, unless `CODESAGE_SESSION_LEDGER=0`, the snapshot also records `worktree`: each path that differed from `HEAD` or was untracked (non-ignored) at snapshot time, capped at 10,000 paths (`truncated`), with a fingerprint in `blob`: the Git blob id, or `stat:<bytes>:<mtime_ns>` for a file over 8 MiB or past the 256 MiB per-capture hashing budget, or `null` when deleted or not a regular file. The Git children behind it (`git diff --name-only --relative <head>`, `git ls-files --others --exclude-standard`, `git hash-object --no-filters --stdin-paths`) run with `-c core.fsmonitor=false` and `GIT_OPTIONAL_LOCKS=0`, so a repository-configured fsmonitor hook never runs, and share a 5 s deadline after which the child is killed and the record is omitted.
  - Session call ledger: after a successful MCP `session_start`, the daemon attributes every later tool call on the same MCP connection and project to that session, appending one JSON line per call to `.codesage/sessions/<session_id>.calls.jsonl`: `{"ts", "tool", "target_handles", "detail", "bytes"}`. `ts` is Unix epoch milliseconds, `detail` and `bytes` are the response's `cost.detail` and `cost.bytes` (`detail` is `null` for tools without detail levels), and `target_handles` holds up to 64 `file:`, `sym:`, or `chunk:` handles read from the response's served evidence, never from the arguments. Extraction skips `next`, `expand`, `recover`, `remedy`, `completeness`, `candidates`, echoed `query` / `input`, notes, commands, the not-served lists (`unindexed_files`, `unsupported_files`, `unscored_files`, `no_symbol_files`, `failed_paths`, `omitted_files`), and any object marked `status: "unresolved"` or `found: false`. Every remaining handle must then name a file present in the project's index (`files` table, read-only open); handles for any other path, such as an unresolved stack frame, a missing file, or a new unindexed file the caller named, are dropped, and an unreadable index drops them all. Query text, snippets, stack traces, and paths that exist only in the arguments are never written. Only per-file evidence tools record handles (`describe`, `find_symbol`, `find_references`, `find_similar`, `list_dependencies`, `search`, `trace_call_path`, `from_trace`, `impact_analysis`, `export_context`, `find_coupling`, the three `assess_risk*` tools, `recommend_tests`, `review_rehearsal`, `find_feature`, `feature_bundle`, `edit_check`); other tools record a call with no handles, error results record no handles, and `help`, `session_start`, and `session_end` are not recorded. A successful `session_start` empties that id's ledger; a later `session_start` on the same connection and project rebinds it. A shim reconnect or daemon restart opens a new connection, so calls after it are not attributed to the earlier session. Calls on a connection with no bound session go to `.codesage/sessions/connections/mcp-<unix>-<pid>-<n>.calls.jsonl`. Lines are appended without fsync, and a ledger stops growing at 2 MiB. Retention runs per directory (`sessions/` and `sessions/connections/`) whenever a ledger is created and each time a ledger grows past another 256 KiB (including when it reaches the 2 MiB cap): it deletes `*.calls.jsonl` files whose mtime is more than 30 days old, then the oldest by mtime until at most 256 files and 16 MiB remain. The ledger being written is never deleted. Between prunes, a directory can exceed 16 MiB by less than 256 KiB per ledger still being written; an idle directory is not pruned until its next write. Ledger failures (read-only directory, symlinked path, unonboarded project) are logged at debug level and never change the tool result. Nothing is written unless `.codesage/index.db` already exists. `CODESAGE_SESSION_LEDGER=0` (or `false`) in the daemon's environment disables recording, the snapshot's `worktree` record and its Git children, and edit detection at `session_end`, which then reports `ledger: "disabled"`, `edited_source: "disabled"`, and zero counts. CLI `codesage session-start` does not bind a ledger.
  - `acted_on` on `session_end` (MCP and CLI): correlates the ledger with edited files. Correlation, not causality. Edited files are, by `edited_source`: `worktree` (paths that differ from the snapshot's `git_head` now, by `git diff --relative` plus untracked non-ignored files, minus paths whose blob id is unchanged since the snapshot's `worktree` record, plus recorded paths now matching `HEAD`), `git_head` (the snapshot has no `worktree` record, so changes present before `session_start` count), or `index` (no Git: indexed files added or removed). `.codesage/` paths are ignored. Edited paths in neither the snapshot nor the current index count only in `edited_unindexed`. Only ledger lines at or after the snapshot's `created_at` second count. Check tools (`assess_risk_batch`, `assess_risk_diff`, `recommend_tests`, `review_rehearsal`, `edit_check`) take the caller's own patch or file list, so their handles echo files the agent already chose or changed; they never count as fetched. A `review_rehearsal` run after editing therefore adds nothing to `fetched_then_edited`; its files appear in `checked` (distinct files check tools returned), `checked_edited` (of those, edited), and `per_tool`. Fields: `ledger` (`recorded`, `absent`, or `disabled`), `calls`, `fetched_then_edited`, `edited_unfetched`, `fetched_unedited` (all three over fetched files from non-check tools), `edited_unindexed`, `checked`, `checked_edited`, `recommended_tests_edited` (edited test files a `recommend_tests` call returned), the first 50 sorted paths behind the first, second, and fifth counts (`*_files`), `per_tool` (`{calls, fetched, fetched_then_edited}` per tool including check tools, `fetched` counting distinct files returned), `ledger_capped` (the ledger reached 2 MiB, so served counts are a lower bound), and `worktree_truncated`. A session with no calls and no edits reports zeros.
- `list_features`: list mapped feature slices, filterable by `kind` (`route`, `cli-command`, `library`, `test-suite`, `service`, `config`, `job`), `language`, or `tag` (0.7.0).
- `find_feature`: given a file path, return the feature(s) that own it. Routes "what slice owns this file?" without scanning by hand.
- `feature_bundle`: curated code bundle for one feature slice (entry + owned + tests + context as primary/related chunks, plus the entry symbol's definition and optionally its callers/callees). Same shape as `export_context` but anchored on the feature's pre-curated file list. `target` (legacy spelling `feature_id`) also accepts `route:METHOD path` and `cmd:name`; several matches are `E_AMBIGUOUS` with their ids, and an unknown one returns `found: false`.

All 22 public tools that return rows accept `detail: "compact" | "standard" | "full"` and `budget_tokens` (an integer of at least 256); `help` and `session_start` do not. Compact defaults apply to `find_references`, `impact_analysis`, `list_dependencies`, `list_features`, `find_feature`, and `describe`; other row tools default to standard. Compact removes source content and detailed risk components while retaining handles, counts, and uncertainty. Full adds available working-tree snippets (`snippet_source: "working_tree"`) and risk decomposition. Snippets cover up to three lines per row, with at most 20 source files of at most 1 MiB each; budgeting may shorten them. Budgets approximate one token as four serialized UTF-8 bytes and cannot exceed the server's per-tool cap. Trimming reports omitted rows and recovery arguments through `completeness`; required evidence and one retained row can exceed the requested budget, disclosed as `cost.budget_exceeded`. Risk tools retain deprecated `verbose` (`true` → full, `false` → standard); `impact_analysis` retains `summary_only` (`true` → compact, `false` → standard). A conflicting explicit `detail` is `E_PARAM`.

Every MCP tool advertises an `outputSchema` (0.7.0); agents that consult it know the result shape before they call. Every successful response also carries a shared envelope, with silence meaning the good case: `tool` names the tool, `cost` reports `{ms, bytes, detail}` (wall time from request receipt to response, including admission wait; exact serialized UTF-8 bytes of the final JSON payload, including the envelope and cost itself, excluding duplicated transport text), plus the applied `budget_tokens` on row responses, and `index` reports `{generation, head, structural, semantic, dirty_paths}`. On errors, `cost.bytes` counts the JSON error contract text block, excluding the readable cause and duplicated transport text; errors do not acquire `structuredContent`. `generation` is a 48-bit digest of the index state (file identity, observer epoch, `data_version`, config digest, coupling policy) whose unequal values prove the state changed, while equal values are only meaningful within one daemon's lifetime, `head` the short indexed SHA, `structural` `behind` (at least one indexed file's HEAD content differs from the index, counted by `files_behind`, with `files_behind_bounded: true` when that count is a lower bound because the comparison stopped at its cap or budget; when the comparison cannot run or stops before finding one it falls back to the indexed SHA not being HEAD), `dirty` (a path in this response differs on disk, which wins over `behind` and `unknown`), or `unknown` (drift could not be determined: git failed, the index carries no commit stamp, or it could not be opened), `semantic` `partial` or `none` for the configured embedding model, and `dirty_paths` the stale paths. A dirty or behind index adds `index.recover {command: "codesage index", cwd, why}` with the absolute project directory. `structural` is omitted only when the index is fresh, and `files_behind`, `files_behind_bounded`, `semantic`, and `dirty_paths` are each omitted when they have nothing to report, and the whole `index` block is omitted when the project holds no index; drift and coverage are measured once per index generation and at most every 30s, so a commit without a reindex surfaces within that window. `completeness {kind, kinds[], recover}` appears only when the answer is not exact: `kind` is the most severe of `kinds` in the order `truncated` > `bounded` > `partial` > `clamped` > `unscored` > `floor`, and `recover` is machine-readable, never prose: `{total, returned, arguments}` for `truncated` (`arguments` advances `offset` only for `search`), `{command}` naming the broader CLI surface or `{tool, arguments}` for `bounded`, `{requested, applied}` keyed by parameter for `clamped`, `{command: "codesage git-index"}` for `unscored`, the per-input reason lists or lexical-failure command and reason for `partial`, and `{reason}` for `floor`. `target {ambiguous, candidates_total}` is injected only on tools that do not already carry a `target`, and only when the input resolved to several entities; `find_symbol`, `find_references`, and `find_similar` always carry their full `target` (`input`, `kind`, `resolved`, `ambiguous`, `candidates_total`, `overloads`) instead. Staleness is derived from the `file:` / `sym:` / `chunk:` / `dir:` handles rows carry, unioned with a residual allowlist for path fields that carry no handle; `edit_check` is annotated too and still starts no watcher.

Deprecation window (opened in 0.35.0, still open): responses emit the envelope alongside the unchanged legacy keys. On the request side the legacy entity-naming arguments (`name`, `symbol_name`, `file_path`, `file_paths`, `feature_id`) and the `impact_analysis` `is_file` / `export_context` `is_symbol` hints are deprecated and still accepted; `find_references` keeps `name`. On the response side, `_meta` (`truncated`, `total_results`, `returned`, `dropped_files`, `clamps`, `coverage`, `stale_files`, `stale_warning`, `test_override`, `ranking_recomputed`) and the per-tool incompleteness fields (`counts_floor`, `bounded`, `truncated`, `callers_truncated`, `reachable_capped`, `reach_walk_capped`, `unmodelled`, `unscored`, `unscored_files`, `unwalked_files`, `partial_files`, `unindexed_files`, `no_symbol_files`, `to_resolution.capped`) are deprecated and still emitted; their removal will also move the payload under `data`. `CODESAGE_ENVELOPE=legacy` in the daemon's environment suppresses the shared envelope except final `cost` accounting; it is read once when the daemon builds its state, like `RUST_LOG`, so changing it mid-life needs `codesage daemon stop`. Legacy mode restores the old keys, not the old staleness coverage: `edit_check` still gains `_meta.stale_files`, and `entry_path` and reachable-test `via` paths still enter the staleness check. `embed_texts`, `rerank_pairs`, and `daemon_stats` are internal and carry final `cost` accounting without the public evidence envelope.

Responses also include ranked `next[]` with at most three evidence-derived `{tool, arguments, why}` calls. Arguments carry an absolute project path and use result handles; each `why` has fewer than ten words. Calls are derived before detail or budget trimming. Empty, unsupported, or terminal evidence returns `[]`; context bundles and `help` terminate the chain, and `session_start` waits for edits. High-risk file evidence can suggest `session_start` with a fresh ID that preserves an existing default baseline. Error results keep the readable cause as the first text block and add one JSON block: `{"tool", "error": {"code": "E_...", "message", "remedy", "candidates"}, "status", "complete": false, "next": [], ...}` (`candidates` only on a target refusal). An ambiguous target can populate `next[]` with candidate-specific calls. `remedy` is `{"tool", "arguments"}`, `{"command"}`, `{"command", "cwd"}`, or `null`, never prose (`cwd` appears only on `E_NOT_ONBOARDED`; a path is never interpolated into a command string). Codes are `E_PARAM`, `E_PROJECT_PATH`, `E_NOT_ONBOARDED`, `E_SCHEMA_TOO_NEW`, `E_NOT_FOUND`, `E_AMBIGUOUS`, `E_EMPTY_INPUT`, `E_OVER_CAP`, `E_MODEL`, `E_DB_BUSY`, `E_SATURATED`, `E_TIMEOUT`, `E_CANCELLED`, `E_SHUTDOWN`, `E_INCOMPLETE`, `E_INTERNAL`; retry-shaped remedies echo the original arguments, and a target naming several entities returns `E_AMBIGUOUS` with every candidate's handle in `candidates` and the first one substituted for whichever argument carried the ambiguous input (`edit_check` retries with the first matching `line` instead). Parameter validation, project routing, `daemon_stats`, and internal-tool failures all use the same block; legacy `status` values are unchanged. Follow-ups are suggestions, not instructions or evidence that unreturned matches do not exist.

Structural MCP queries apply request-local overlays for edits to already indexed files, within limits of 50 dirty files, 2 MiB of changed source, and a 500 ms preparation budget. The budget includes cold parser-query initialization. Successful overlays report `index.structural: "overlay"` and `index.overlay` evidence; exhausted preparation retains indexed facts and discloses the reason. Overlays do not rewrite persistent structural rows. C++ queries capture shallow declarations, then apply shared AST filters to preserve extracted names, kinds, ranges, and function fingerprints while reducing cold initialization.

## MCP runtime

`codesage mcp` is the stable client entrypoint. It runs as a stdio shim, starts or connects to the per-user Unix-socket daemon, and forwards MCP JSON-RPC unchanged. The daemon hosts the real MCP server and owns shared project/model/reranker pools across main sessions and subagents.

On Unix, a shim-spawned daemon starts in its own session and process group. Terminating the spawning shim's group or closing its controlling terminal leaves the shared daemon available to other clients. The daemon still exits after its no-client idle timeout or an explicit `codesage daemon stop`; a foreground `codesage daemon` remains attached to its invoking session.

Indexing reuses a running daemon's embedding model. If that daemon reports `E_SHUTDOWN` or its connection breaks, the indexer opens a fresh session before falling back to private embedding. Reconnection waits up to 15 seconds for a same-build successor at the existing socket path, within the batch's 240-second retry budget. The indexer does not start a replacement daemon itself. If none returns, that batch embeds privately; later batches can reconnect. Reconnected requests retain the pass's semantic fingerprint, and a fingerprint mismatch fails the pass without private fallback. Unknown daemon error codes are not retried.

CLI `search` and `export` reuse the daemon's reranker through internal `rerank_pairs`, omitted from `tools/list`. Requests are capped at 32 documents, 65,536 bytes per text, and 1,048,576 bytes total; the CLI splits batches and uses private inference for oversized individual texts. Without a daemon, private initialization remains eager. Remote inference failures retain warning/pre-rerank-order behavior without loading a second model; already-running native inference cannot be forcibly cancelled.

`codesage mcp --project <abs root>` makes the server default the per-call `project` argument to that root when a `tools/call` omits it. Set automatically by `codesage install` for agents without a CodeSage plugin (Codex, opencode), which otherwise have no way to inject the project path. With no `--project` (the Claude-plugin path) the shim raw-copies stdio with zero overhead.

The daemon co-trusts every process under the same Unix UID. Runtime dirs, socket mode `0o600`, and `SO_PEERCRED` keep other users out, but a compromised same-UID agent can ask the daemon to read any onboarded project index. Use a separate Unix user for untrusted agents that need project isolation. MCP tools are capped for agent safety; CLI commands are the operator surface and intentionally keep broader limits unless a command documents its own cap.

Consistency during reindex: the structural indexer commits in batches of 50 files, so cross-file queries issued while a large reindex is running can see a blend of pre- and post-change state. The per-response `index.dirty_paths` annotation (deprecated `_meta.stale_files`) flags results referencing files that changed on disk but aren't reindexed yet. Both windows close when the index pass finishes.

Use `codesage mcp --direct` only when debugging the old single-process stdio path. Use `codesage daemon` to run the foreground daemon explicitly. Socket state lives under `$CODESAGE_DAEMON_RUNTIME_DIR`, `$XDG_RUNTIME_DIR/codesage`, or `/tmp/codesage-$UID`; the socket name includes the running binary's version and executable metadata so rebuilt binaries don't attach to stale daemons.

### Daemon management

- `codesage daemon` runs the daemon in the foreground (the default action).
- `codesage daemon status` prints the running daemon's pid, socket path, and log path; exit 1 if not running.
- `codesage daemon stats --json --recent N` queries the existing same-build daemon without starting one; `N` is 0 through 256. It reports bounded request/execution detail, aggregate outcomes, cache reuse, and current work limits. The internal `daemon_stats` tool is not advertised to agents.
- `codesage daemon stop` sends SIGTERM, waits up to 10s for cleanup, and reports.

Runtime files per daemon: `mcp-<version>-<key>.sock` (Unix socket, 0o600), `mcp-<version>-<key>.pid` (text pid), `mcp-<version>-<key>.lock` (start-lock during spawn), `mcp-<version>-<key>.log` (daemon stdout + stderr). The log is rotated when it crosses 4 MiB; three generations are retained (`.log`, `.log.1`, `.log.2`).

Logical request completion does not release a physical execution lease. Shared ranking waiters detach independently; native inference and nested download workers retain capacity until actual exit. Work-control error metadata reports `phase`, `work_continuing`, and `complete: false`. Session cancellation after atomic persistence does not roll back the snapshot; retained diagnostics track `persistence_committed` even if delivery was cancelled. See README for the operator inspection path and `bench/daemon-performance/README.md` for the measurement and acceptance procedure.

### Tracing

The daemon inherits the **first** spawning shim's environment, including `RUST_LOG`. Setting `RUST_LOG=codesage=debug` on the initial `codesage mcp` invocation that boots the daemon raises the daemon's log level for its entire lifetime; subsequent shims with different `RUST_LOG` values don't reconfigure the running daemon. To change filters mid-life, `codesage daemon stop` and let the next shim restart it under the new env.

The daemon writes tracing to `mcp-<version>-<key>.log` in the runtime dir; check that file first when a tool call hangs or an MCP session won't initialize. SIGTERM/SIGINT trigger graceful shutdown (socket + pid file removed before exit).

`doctor --docs [PATH...]` scans markdown for claims that can be checked against the index and working tree and reports the ones that no longer hold: backticked repo-relative file paths and relative link targets that no longer exist, `path:line` anchors past the end of the file or whose nearby backticked symbol has moved, `Owner::member` tokens whose owner is indexed but has no such member, and `UPPER_SNAKE` or Google-style `kCamelCase` constants whose stated value (`= 5`, `is 5`, `defaults to 5`, `(default 5)`) differs from the source literal. Explicit PATH arguments bypass `exclude_patterns` (the `git add -f` convention); non-markdown arguments are skipped, and an unreadable directory or non-UTF-8 or unreadable file is named under `files_failed` without aborting the sweep. Fenced code (including blockquote and list containers), indented code (four columns, or four past a list item's content column), HTML comments, globs, URLs, `<placeholder>` tokens, `foo`/`bar`/`baz`/`qux` path segments, `..` segments, env vars, flags, and single words are not claims; a line with an unclosed code span is skipped entirely, links and anchors on it included. From a document outside the repo, symbol claims are not reported at all, and a missing path is reported only with a concrete relocation: a single same-named indexed file (not a basename the index holds twice, nor a generic one like `README.md` or `mod.rs`), or the module having become a directory that holds indexed files of the same kind (`<module>.rs` → `<module>/`). Read-only over the index; exit 0 unless `--strict` (exit 1 when anything drifted, a file failed, or no documents were checked; a checked document with zero claims still succeeds); `--json` emits `{ files, files_skipped, files_failed, claims_checked, drifted[] }`.

## Git history intelligence (V2b slice 1)

Schema migration `0018_git_author_events` retains per-file author events. After `git-index --full`, risk responses include informational `author_concentration`: author count, dominant share, effective authors (inverse squared-share sum), and `bus_factor` (fewest identities covering at least 50% of weighted commits). Events use a 180-day half-life and a 730-day window. Identity is normalized email, falling back to normalized name; it is not a verified person count, and mailmap changes are not applied retroactively. Legacy or absent author history remains unknown. This signal does not affect the risk score.

Author-concentration notes distinguish absent indexed events from events outside the evaluation window. That evaluation uses the file's newest indexed commit as its anchor, or query time when no file commit is available; filtered-event notes name the actual anchor. The indexing window has separate persisted provenance in migration `0021_git_history_anchor`. Legacy or older-writer provenance reads unknown until the next `codesage git-index` pass, which rebuilds in full because such state carries no exclusion fingerprint (see the modes below); pinned-window notes use the recorded source and epoch rather than assuming HEAD.

`codesage git-index` measures its 730-day history window and its decay reference from HEAD's own committer epoch, not the wall clock, so a pinned or archived checkout indexes its history instead of returning nothing; the window is stamped `730d@HEAD`, falling back to `730d@now` only when there is no HEAD. `codesage git-index` runs `git log --numstat` and populates `git_files` (per-file churn score with τ=180d decay, fix count, total commits, last commit), `git_co_changes` (file pair weights, min count 3, plus migration `0017`'s `first_observed_at`, `window_mask` (bit `(ts / 90d) % 64` per shared commit, keyed to the unix epoch), and `windows = popcount(window_mask)`), and `git_index_state` (last indexed SHA). Co-change confidence is not stored: `find_coupling` derives P(other | this) as `count / git_files.total_commits` of each side.

`git-index` reads `git log` with `--no-show-signature` and `--root`, and fails rather than reporting success on output it cannot parse. It walks history children-first and keys renamed files to their HEAD path, including a merged branch's edits to the old path; copies are not followed. An incremental pass re-keys stored rows for paths renamed within its range, and rescans in full when a file is renamed onto a path that already has history, when two stored files are renamed onto one path, or across the test-like boundary. A branch edit to the old path indexed in a later pass than the rename stays on the old path until `git-index --full`; history indexed before rename support needs one `git-index --full` to re-key.

Three modes, selected via flags on `codesage git-index`:

- `--full`: fresh rescan. Drops existing rows and walks the entire history. Use after big rebases that rewrite a lot of history, or to rebaseline weekly.
- `--incremental`: scans only `<last_sha>..HEAD` and additively updates counters. Scales pre-existing weights by `exp(-Δt/τ)` so exponential decay stays mathematically exact across runs. Co-change observations below count 3 are retained across passes but hidden from coupling queries until they reach that threshold. Run `codesage git-index --full` after upgrading to recover observations discarded by earlier versions. `window_mask` composes exactly (`mask |= delta`, `first`/`last` take MIN/MAX) because window bits are keyed to a fixed epoch, so `windows` and `span_days` match a full rescan after every incremental pass for rows written by an 0017-aware `--full` (commits inside the 730-day history window; a `--full` still rebaselines rows whose oldest commits have aged out). Rows indexed before 0017 (`first_observed_at IS NULL`) are left unbaselined by incremental passes and keep `span_days` 0 / `recurrence` 1 until `codesage git-index --full`.
- default (no flag, `Auto`): incremental if valid prior state exists and its SHA is an ancestor of HEAD, else full.

Auto and `--incremental` behave the same way. Both also rescan in full when the effective exclusion policy (`DEFAULT_EXCLUDE_PATTERNS` plus `[index] exclude_patterns`, order- and duplicate-insensitive, together with the test-like pattern set and the per-commit co-change file cap) differs from the fingerprint stored with the last pass (migration `0025_git_exclusion_fingerprint`), including when none is stored: an index written before 0025, or last written by an older binary, whose state update clears the column. So the first pass after upgrading is a full rescan, and editing the exclusions drops the newly excluded paths from `git_files`, `git_co_changes`, and `git_author_events` without `--full`.

`codesage install-hooks` now registers `post-commit`, `post-merge`, `post-checkout`, and `post-rewrite`, each running `codesage git-index --incremental` in the background. Rebased or force-updated history triggers a full rescan automatically (incremental detects when the stored SHA is no longer an ancestor of HEAD and falls back to full).

Hook runs are single-flight through `.codesage/hook-index.lock/`; the winner writes its pid to `<lockdir>/pid` and logs `hook start pid=N` / `hook exit=N pid=N` to `.codesage/hooks.log` from its EXIT trap (SIGINT/SIGTERM route through it; a signal trap runs only after the in-flight indexer child returns). Reaping is single-winner across concurrent fires (a `hook-index.lock.reap` mutex). A lock whose pid is dead or belongs to a non-hook process is reaped by the next fire regardless of age; a lock without a pid file (pre-upgrade hook) is reaped once 30 minutes old; a lock held by a live hook run is never reaped, by the hook or by doctor (a hung run is removed by hand). When `ps` is unusable, liveness alone decides. `codesage doctor` reports the lock state under `hook_health`, reaps dead-pid and stale pidless locks itself, and warns on a live run older than 30 minutes; `project_overview` only reports.

Two MCP tools consume the tables:

- `find_coupling(project, target, limit)`: top-N files that historically change together with the input, weight-sorted with non-recurring pairs at half weight by default; rows carry `recurrence`, `span_days`, `span_known`, `recurring`, `p_cochange`, and `p_reverse` (deprecated spellings `confidence` / `reverse_confidence`). CLI: `codesage coupling <file>` prints the measurements and marks one-offs and unknown spans.
- `assess_risk(project, target, verbose?)`: composite risk score (0..1) from churn percentile + fix ratio + depth-2 reverse-dep pressure + coupling pressure + test gap. Returns the score plus human-readable notes for PR descriptions; `verbose: true` (shared with `assess_risk_batch` / `assess_risk_diff`) adds the per-signal decomposition and `top_coupled`. CLI: `codesage risk <file>` (always verbose).

The indexer filters the same `DEFAULT_EXCLUDE_PATTERNS` as the structural indexer, plus NEWS/UPGRADING/CHANGELOG variants (they touch every commit so they pollute coupling).

## Feature mapping + trust boundaries (shipped 0.7.0)

`crates/features/` runs after structural and before semantic indexing on every `codesage index`. It maps the project into **behavior-keyed slices** (entrypoint + owned files + context files + tests + aggregated trust boundaries + tags) and derives **per-file trust boundaries** from imports/includes/calls and Java framework roles.

Mappers are deterministic (no LLM) and language-local:

| Mapper | Detects |
|---|---|
| Rust | `src/main.rs`, `src/bin/*.rs`, `src/lib.rs`, Cargo workspace members, `crates/*`, integration tests under `tests/*.rs`, and syntax-backed `rmcp::ServerHandler` implementations as MCP service entrypoints |
| PHP | `composer.json` bins + scripts, PSR-4 autoload roots, php-src `ext/*/config.{m4,w32}`, Laravel `routes/{web,api,console,channels}.php` |
| C / C++ | tree-sitter `main()` detection, `bin_PROGRAMS` / `lib_LTLIBRARIES` from autotools, `add_executable` / `add_library` from CMake |
| Python | `pyproject.toml [project.scripts]` (module-resolved entry path), `setup.py` `entry_points`, top-level `if __name__ == "__main__":` modules |
| JS / TS | `package.json` `bin` + selected scripts (`start`, `build`, `test`, `lint`, `typecheck`, `format`), Next.js `app/**` and `pages/**` routes |
| Go | `cmd/<name>/main.go` and a repo-root `main.go` when declared `package main` |
| Java | Maven modules with conventional `src/main/java/` sources grouped by source-evidenced web-entrypoint, application-service, persistence-boundary, external-client, configuration, and framework-component roles |

Rust MCP service detection follows named imports and explicit `extern crate` bindings to `rmcp::ServerHandler`, rejecting local lookalikes. Implicit external-crate paths require a known Rust 2018, 2021, or 2024 edition; uncertain workspace ownership, macro-generated names, and module paths can leave an implementation unclassified. Local wildcard inspection is bounded; following a wildcard into another file also requires a known module directory.

Tables (schema migration `0009_feature_tables`): `features`, `feature_files` (per-feature path×role refs), `feature_trust_boundaries` (per-feature boundary set).

php-src extensions retain their build-config feature and map C/C++ sources and headers into directory-keyed `php-ext-source-group` features with at most 40 owned files each. Oversized directories split by child directory, then sorted filename ranges for flat directories; no source is dropped merely to meet the group bound. Groups are low-confidence directory associations, not inferred runtime behavior. The existing per-extension scan limit of 2,000 admitted source files produces a partial mapper error when exceeded. Exclusions, generated arginfo files, and test files are removed before partitioning. Standalone PHP-extension and Laravel mapping retain their existing shapes.

Grouped features expose `entrypoints: [{path, symbol}]` for their PHP functions and methods (`0029_feature_entrypoints`); other features omit an empty list. `feature-show`, `list_features`, `find_feature`, and feature descriptions retain these anchors, and feature bundles prefer their indexed definitions and bodies within the requested limit. A group's directory is its identity, not a recursive ownership edge: its explicit file rows define its scope. Repeated maps of unchanged input preserve IDs; changing an API within an existing group updates its anchors without changing the group ID. Indexing after upgrade remaps existing features through `MAPPER_OUTPUT_VERSION`.

Trust-boundary rule tables (`crates/features/src/trust_boundary_rules.rs`) cover Rust, PHP, C/C++, Python, Go, Java, and JavaScript/TypeScript plus Laravel facades. Java also derives roles from exact qualified or imported framework annotations, repository inheritance, and HTTP client fields: web-entrypoint adds `network` / `user-input` / `serialization`, persistence-boundary adds `database` / `serialization`, and external-client adds `network` / `external-api` / `serialization`. The shared classifier checks lexical type declarations and parameters, same-package top-level declarations within each source root, and supported static client-builder type imports. The classifier rejects name/layout-only signals and skips role sources over 1 MB; import derivation reads current source up to the structural 10 MiB bound. Custom meta-annotations and Maven source roots are not modeled. Changed, added, or removed Java inputs cause the next structural index to reparse unchanged Java dependents. Indexing and source-aware backfill merge role tags with import tags in one deduplicated per-file set; `map` reparses current Java source for these tags before aggregating indexed file rows into features, and reports unavailable source or a 50,000-file discovery cap as a partial mapper outcome retaining existing slices. Boundaries are: `network`, `filesystem`, `process-exec`, `secrets`, `database`, `user-input`, `external-api`, `serialization`, `auth`, `concurrency`. Per-file rows live in `file_trust_boundaries` (migration `0008`), with a `boundaries_derived_at` marker (migration `0010`) used by the indexer's targeted backfill to avoid re-running derivation on rule-clean files.

Java declaration context requires complete UTF-8 source reads. An unavailable context prevents structural Java rewrites, preserves existing rows and boundaries, reports failed paths, and marks interpretation stale for retry; independent non-Java files still proceed. Single static imports distinguish supported/source-declared member types from source-declared methods, fields, interface constants, and enum values. An unresolved same-name static member leaves wildcard role inference unclassified.

Qualified framework names resolve their first component through lexical, explicit-import, same-package, and source-declared wildcard type evidence before accepting a package spelling. Conventional Maven test sources consult their own declarations and the same module's main source root; main sources exclude test-only declarations, and modules remain isolated. Names use bounded AST identifier components, skipping comments and type-use annotations. Client fields normalize array element types across type and declarator dimensions, without promoting generic type arguments or annotation contents to client evidence.

On-demand ordinary imports use accessible source-declared top-level and member types; on-demand static imports use accessible static member types and the supported external builder roster. Public, package, and private declaration access filters import candidates. Both import forms feed the same type-candidate lookup while imported methods, fields, and enum values remain outside it. Interface and annotation-type `constant_declaration` fields share class `field_declaration` client checks.

`assess_risk` consumes the per-file rows: `0.10 * min(boundary_count/5, 1.0)` adds to the composite score, capped at 5 boundaries. The `notes[]` line `"crosses N trust boundaries (X, Y, Z) — security review recommended"` fires when ≥3 boundaries are crossed. The signal lands in `RiskAssessment.trust_boundaries: Vec<TrustBoundary>`.

`[index].exclude_patterns` from the project's `.codesage/config.toml` are honored throughout the mapper crate via `MapperContext.excludes`. Mappers emit candidate seeds, the orchestrator filters entry paths and per-record file refs against the globset, so feature output matches the structural indexer's file-set contract.

The MCP surface (`list_features`, `find_feature`, `feature_bundle`) sits on top of these tables. The CLI surface (`map`, `features-list`, `feature-show`, `feature-for`, `feature-bundle`, `trust-boundaries`) mirrors it for terminal use.
