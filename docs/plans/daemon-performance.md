## Key decisions

### Request and execution ownership

Track logical requests and physical executions independently. A request acquires a bounded logical slot before cache lookup. A stable overview hit assembles live SQL and freshness fields under bounded interactive capacity, without an analysis execution slot. If validation requires recomputation, release the interactive lease and read transaction before acquiring analysis capacity and reopening a pinned snapshot under the original deadline. Session assembly still requires analysis capacity because it computes current import cycles even when ranking is cached. A waiter joining a flight holds no execution slot while waiting. The shared flight independently acquires physical capacity, so a single-slot configuration cannot deadlock through nested admission.

Bound logical requests, queued physical work, and running work separately. Use interactive database, analysis, and native work classes. Reserve interactive capacity, and select eligible projects fairly with per-project execution limits. A waiting project must not hold global execution permits while waiting for its project limit. Canonical path aliases share the same limits. Control operations such as initialize, ping, tool inventory, and diagnostics remain outside expensive-work admission.

Physical permits and completion accounting belong to the actual execution, including any nested worker that outlives its parent. Dropping a handler or removing a flight from the lookup map never releases physical capacity prematurely. Bound and prune project gate records without removing gates still referenced by requests or executions.

Include generation probes in physical execution diagnostics. Link their tickets to the caller before queueing, retain tickets for the actual worker lifetime, and preserve continuation status when the awaiting future is cancelled. A physical lease without a corresponding execution record must not cause a false stopped-work response.

### Persistent cancellation

Introduce a small synchronous cancellation/deadline primitive that can be consumed by storage, graph, and embed without dependency cycles. A suitable location is a dedicated module in the existing dependency-free protocol crate; Tokio coordination remains in CLI. Alternatively, pass cancellation callbacks into lower layers if this avoids exposing runtime types. Settle this interface before parallel edits.

Record the first terminal stop reason. Observe protocol cancellation, connection closure, server deadline, loss of all consumers, and shutdown. Queue time counts toward a request deadline. A shared producer has a finite creation-time deadline that later callers cannot extend; each waiter retains its own request deadline.

Use persistent checkpoints between risk candidates, graph levels, and bounded loop intervals. Compose the outer deadline with existing `WalkBudget` limits rather than resetting a budget per candidate. Check cancellation during model-lock acquisition and immediately before and after operations that cannot be interrupted.

For request-owned SQLite connections, install cancellation before initialization queries. Combine a progress handler observing persistent stop state with an interrupt handle for active statements. An interrupt on an idle connection is a no-op, so an interrupt alone cannot close the race before the next statement. Test busy-lock waits separately; use bounded MCP read lock waits and an explicit retryable database-busy result if interruption cannot stop the existing busy handler promptly. Preserve ordinary database errors when cancellation was not requested.

Change `crates/cli/src/daemon_embed.rs::DaemonEmbedder::call` to send protocol cancellation on timeout, following `query_reranker.rs`. Bound sending, response waiting, and cancellation delivery within one outer deadline; cancellation notification must not block indefinitely on a non-reading peer. Connect transport EOF/read errors to service cancellation without waiting for the normal response drain. A timeout confined to an external client is not observable by the server; finite producer deadlines cover that case.

ONNX calls and other noninterruptible sections may continue after a response timeout. Retain their work leases until actual completion and expose continuation in diagnostics. In particular, account for the worker spawned by `crates/embed/src/model.rs::hf_with_deadline`; the outer closure returning must not hide an active download worker. Shutdown closes admission, signals cancellation, and drains tracked work before the existing final process-exit fallback.

### Ranking completeness and cache validity

Cache top-50 `(file, score)` rows in shared daemon state. Overview uses the first ten. Refactor session construction to accept the same ranking only when it matches the rest of the baseline's database snapshot.

Introduce typed completeness provenance before caching. In the pre-change baseline, `compute_top_risk` discards a fallback failure flag, and `assess_risk_batch` can return success after omitting a failed cycle signal. Neither case is cacheable. Cancellation and deadline errors bypass per-file fallback. Preserve ordinary fallback when every required score component is recovered. Existing intentional bounded graph floors remain valid under their documented semantics; distinguish them from execution failure.

Key reuse by canonical root, database file identity, observer epoch, same-connection `PRAGMA data_version`, bounded config digest, and effective score-affecting policy, including coupling recurrence. Capture policy once and compute using that captured value. Use a dedicated read-only observer that performs no writes. Keep epochs unique across eviction and recreation. Reopen the observer when the database file changes, and verify identity around opening and generation probes.

Compare generation before and after calculation and before admitting cached data into a request snapshot. Do not compare `data_version` values from different connections. The counter is an invalidation signal, not a database snapshot identifier.

Keep unchanged semantic read-opens from committing timestamp-only model-registration updates: such writes advance the observer's generation and invalidate otherwise reusable rankings. Preserve registration of missing or changed metadata, case-alias cleanup, and write/rebuild timestamp semantics. Verify both storage generation stability and overview reuse across an intervening semantic query; do not suppress genuine semantic-index mutations to retain a cache hit.

Compute database-derived analysis against a pinned read transaction. Probe generation before opening the computation connection, then open and pin its snapshot and probe again; probing only after opening can accept a connection to a replaced database inode. Apply this protocol to both overview and session reuse, including agreement with the cached ranking's generation. On mismatch, recompute ranking on the pinned connection within the original deadline. This avoids persisting old risk rows alongside newer files, cycles, or counts. Test replacement between the first probe, connection opening, and snapshot pinning with deterministic barriers.

Never use an immutable SQLite fallback for generation observers or controlled reads: those connections must observe external commits and retain cancellation behavior. Check the opened connection against its pathname, in addition to surrounding device/inode probes, before cache publication or reuse; pathname probes alone miss an intermediate replacement restored before the next probe. Bound config hashing and reject non-regular files without blocking on FIFOs. If only cache validation is unavailable (a config probe or unsupported opened-file check), use the uncached structural path under the same admission and deadline rules; do not turn a cache optimization into a new structural-tool failure. Keep missing config as a stable sentinel, and never downgrade database, scoring, cancellation, or deadline failures to cache unavailability. Replacement tests do not establish that arbitrary in-use SQLite database/WAL renames are safe; SQLite explicitly excludes that operation from its consistency guarantees.

If indexing changes during a pinned computation, return the complete result for that read snapshot with appropriate change/freshness disclosure and omit cache publication. Do not retry repeatedly or fail solely because another connection committed. Keep Git freshness and rendering live; do not imply that Git, working files, and SQLite form one atomic snapshot. Release read transactions promptly and measure WAL/checkpoint effects during indexing.

Distinguish observed index changes from unavailable cache validation. A failed config probe or unsupported identity check proves only that cached ranking cannot be reused, not that the index changed. Report ranking recomputation without asserting an index mutation unless generation evidence establishes it; preserve identical disclosure in text and structured responses.

Check session cancellation immediately before atomic snapshot persistence. Once persistence commits, cancellation cannot promise rollback. Test the commit-versus-response race and record whether persistence completed even if the response cannot be delivered. Update retained request diagnostics if persistence completes after logical cancellation; response delivery and persistence are separate outcomes.

### Single-flight and retention

One flight owns its control, deadline, physical work lease, and result. Individual waiters own logical request slots. Cancelling one waiter leaves the others attached. When the last waiter leaves, mark the flight abandoned and remove it from joinable state, then signal cancellation. A later caller starts a new flight; execution IDs prevent late completion from overwriting it. Resolve completion-versus-abandonment under one consistent synchronization protocol.

Cache only complete stable-generation success. Do not cache errors, panic results, cancellations, abandoned results, or rankings with failed score components. Bound ready results to 32 canonical-project entries and 2 MiB of accounted payload, including vector and string capacities rather than only retained lengths. Return oversized successful results without retaining them. Do not retain the 16 MiB request-local walk cache.

Bound observer connections, project records, active flights, retired executions, retained outcomes, and diagnostic detail as well as ready payload. Ready observer entries count against the project cache cap; observers pinned by active work count against physical admission limits. Retired work remains charged until it exits. Avoid blocking SQL, filesystem work, or await points while holding a global cache lock.
